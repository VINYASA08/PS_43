## 2. Logic Chain

1. **Network Connectivity & Security Permissions**:
   - In `ApiClient.kt`, network calls target `http://10.0.2.2:3000/api/*`.
   - Android OS enforces network sandbox boundaries: apps without `<uses-permission android:name="android.permission.INTERNET" />` cannot open network sockets.
   - Furthermore, Android 9.0 (API 28) and higher prohibits cleartext HTTP traffic by default. Because development environments communicate over plaintext HTTP with the local Next.js server, `android:usesCleartextTraffic="true"` is required. Both elements are present in `AndroidManifest.xml` and properly merged into the final APK manifest.

2. **Data Serialization Resilience**:
   - Backend APIs may return polymorphic or evolving JSON structures as features roll out.
   - In `DomainDistribution`, all fields have default values (`domain = ""`, `count = 0`, `name = ""`). In `ApiClient.kt`, Ktor's `ContentNegotiation` installs `kotlinx.serialization` with `ignoreUnknownKeys = true` and `isLenient = true`.
   - Therefore, missing fields, unexpected extra fields, or slight discrepancies between web and mobile do not crash the Kotlin application with a `SerializationException`.

3. **3-Track Triage System Parity**:

   - The `Challenge` data class in `Models.kt` incorporates `track: String = "TRACK_A_INNOVATION"`, `trackRouting: String? = null`, and `triageReasoning: String? = null`.
   - This ensures exact schema parity with the web API endpoints (`/api/challenges`, `/api/mobile/challenges`, and `/api/track/[id]`).

## 3. Adversarial Challenges & Edge-Case Stress-Testing

### Challenge 1 [Low / Security]: Unconstrained Cleartext Traffic in Release Builds
- **Assumption Challenged**: Setting `android:usesCleartextTraffic="true"` on `<application>` is sufficient for development and production.
- **Attack Scenario**: If the application is built and deployed in production without overriding this flag, an adversary on an insecure public Wi-Fi network could perform Man-in-the-Middle (MitM) inspection or payload injection of citizen grievance submissions or administrative credentials.
- **Blast Radius**: Eavesdropping or credential interception on unencrypted production connections (CWE-319).
- **Mitigation**: Introduce a `res/xml/network_security_config.xml` that permits cleartext HTTP exclusively for `10.0.2.2` and `127.0.0.1` in debug mode, while enforcing TLS 1.3 / HTTPS for all remote domains in release configurations.

### Challenge 2 [Low / Portability]: Hardcoded `10.0.2.2` Endpoint in `ApiClient.kt`
- **Assumption Challenged**: Mobile clients will only ever run inside the standard Android Studio Emulator.
- **Attack Scenario**: If tested on a physical Android handset via local Wi-Fi, an alternative emulator (e.g. Genymotion using `10.0.3.2`), or compiled for iOS/Desktop targets (`iosMain`, `desktopMain`), all network requests will fail immediately with connection timeouts because `10.0.2.2` is a host-loopback alias specific to the standard Android emulator.
- **Blast Radius**: Non-emulator and non-Android runtime targets will fail network operations.
- **Mitigation**: Extract `baseUrl` into a configurable property or Koin dependency module injected at runtime based on build flavor or environment variable.

### Challenge 3 [Low / Build Hygiene]: Kotlin Hierarchy Template Deprecation Warning
- **Assumption Challenged**: Gradle multiplatform build configuration is free of deprecation friction.
- **Observation**: Gradle output emitted:
  `w: The Default Kotlin Hierarchy Template was not applied to 'project ':shared'': Explicit .dependsOn() edges were configured for the following source sets: [iosArm64Main, iosMain, iosSimulatorArm64Main, iosX64Main]`.
- **Blast Radius**: Deprecation warning in Gradle 8.x; could cause build failures upon upgrade to Kotlin 2.0.
- **Mitigation**: Add `kotlin.mpp.applyDefaultHierarchyTemplate=false` to `mobile/gradle.properties` or adopt modern hierarchy template declarations.
